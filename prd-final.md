# PRD: учебная система автоматизации барбершопа

## 1. Цель проекта

Создать полноценную систему записи для барбершопа, которую студент сможет собрать поэтапно, запустить в интернете, показать как портфолио и затем адаптировать под реального клиента.

Проект должен решать практическую задачу:

- клиент видит сайт барбершопа;
- выбирает услугу, барбера, дату и время;
- записывается через сайт или Telegram Mini App;
- backend проверяет, можно ли создать запись;
- запись сохраняется в общей базе данных;
- Telegram-бот отправляет подтверждения и напоминания;
- администратор управляет услугами, барберами, расписанием и записями;
- владелец видит базовую аналитику.

Главная учебная цель — показать студенту полный путь данных:

`интерфейс → API → бизнес-логика → база данных → уведомления → админка → деплой`.

---

## 2. Для кого проект

### Клиент

Клиент может:

- посмотреть услуги и цены;
- посмотреть барберов;
- выбрать услугу;
- выбрать барбера или вариант «Любой свободный»;
- выбрать дату и свободное время;
- записаться;
- посмотреть свои записи в Telegram Mini App;
- отменить или перенести запись;
- получить уведомление о записи;
- получить напоминание за день и за 30 минут;
- оставить отзыв после визита.

### Администратор / владелец

Администратор может:

- войти в админ-панель;
- добавлять и редактировать барберов;
- добавлять и редактировать услуги;
- задавать рабочие дни и часы;
- задавать обеды, выходные, отпуск и другие исключения;
- видеть записи;
- создавать запись вручную;
- переносить и отменять записи;
- отмечать завершённую запись или неявку;
- смотреть отзывы;
- смотреть базовую аналитику.

### Барбер

В MVP отдельный кабинет барбера не нужен.

Барбер может получать Telegram-уведомления о:

- новой записи;
- переносе;
- отмене.

## 3. Состав продукта

Проект состоит из нескольких частей.

### 3.1 Сайт

Содержит:

- главную страницу;
- описание барбершопа;
- услуги и цены;
- карточки барберов;
- отзывы;
- контакты;
- кнопку «Записаться»;
- страницу записи.

### 3.2 Telegram Mini App

Позволяет:

- выбрать услугу;
- выбрать барбера;
- выбрать дату и время;
- создать запись;
- посмотреть свои записи;
- отменить или перенести запись.

### 3.3 Telegram-бот

Используется для:

- `/start`;
- подтверждений;
- уведомлений;
- напоминаний;
- запросов отзывов;
- deep-link привязки записи с сайта к Telegram.

### 3.4 Backend API

Один backend обслуживает:

- сайт;
- Telegram Mini App;
- Telegram-бот;
- админ-панель.

Backend:

- принимает запросы;
- валидирует данные;
- выполняет бизнес-логику;
- проверяет свободное время;
- работает с базой данных;
- возвращает ответы клиентам.

### 3.5 База данных

Хранит:

- услуги;
- барберов;
- клиентов;
- графики;
- перерывы;
- исключения;
- записи;
- отзывы;
- настройки.

### 3.6 Админ-панель

Позволяет управлять системой без прямого доступа к базе данных.

### 3.7 Аналитика

Показывает:

- количество записей;
- выручку;
- популярные услуги;
- загрузку барберов;
- отмены;
- неявки;
- возвращаемость клиентов;
- загрузку по дням и часам.

## 4. Главный пользовательский сценарий

1. Клиент открывает сайт или Telegram Mini App.
2. Выбирает услугу.
3. Выбирает барбера или «Любой свободный».
4. Выбирает дату.
5. Интерфейс запрашивает у backend доступные слоты.
6. Клиент выбирает время.
7. Frontend отправляет запрос на создание записи.
8. Backend проверяет:
   - существует ли услуга;
   - может ли выбранный барбер выполнить услугу;
   - работает ли барбер в это время;
   - нет ли обеда, выходного или другого исключения;
   - помещается ли услуга в рабочее время;
   - не занят ли этот временной интервал;
   - не слишком ли поздно или рано создаётся запись.
9. Если всё корректно — backend сохраняет запись в PostgreSQL.
10. Если слот уже занят — backend возвращает конфликт, а интерфейс предлагает выбрать другое время.
11. Клиент получает подтверждение.
12. Система отправляет напоминание за день и за 30 минут до записи.
13. После визита система запрашивает отзыв.

## 5. Функциональные требования

### 5.1 Услуги

Услуга содержит:

- название;
- описание;
- длительность;
- цену;
- активность.

Для конкретного барбера можно:

- отключить услугу;
- переопределить цену;
- переопределить длительность.

### 5.2 Барберы

Барбер содержит:

- имя;
- фото;
- описание;
- опыт;
- портфолио;
- список услуг;
- рейтинг;
- график.

### 5.3 Расписание

Для каждого барбера задаются:

- рабочие дни;
- время начала и окончания работы;
- обед;
- выходные;
- отпуск;
- больничный;
- разовые исключения.

Также возможно закрытие всего барбершопа на выбранный период.

### 5.4 Свободные слоты

Слоты рассчитываются backend'ом.

Система должна учитывать:

- длительность выбранных услуг;
- рабочее время;
- обеды;
- исключения;
- существующие записи;
- минимальное время до записи;
- максимальный горизонт записи.

Пользователь не должен видеть занятые или невозможные слоты.

### 5.5 Создание записи

Запись содержит:

- клиента;
- барбера;
- услуги;
- дату и время начала;
- дату и время окончания;
- итоговую цену;
- итоговую длительность;
- источник записи;
- статус.

Двойная запись одного барбера на пересекающееся время должна быть запрещена на уровне PostgreSQL.

### 5.6 Отмена и перенос

Клиент может отменить или перенести запись до заданного лимита времени.

По умолчанию:

- отмена и перенос разрешены не позже чем за 30 минут до начала.

### 5.7 Уведомления

Через Telegram-бота отправляются:

- подтверждение записи;
- уведомление о переносе;
- уведомление об отмене;
- напоминание за день;
- напоминание за 30 минут;
- запрос отзыва после визита.

Напоминания должны быть идемпотентными: повторный запуск фоновой задачи не должен отправлять одно сообщение несколько раз.

### 5.8 Отзывы

После визита клиент получает запрос оценки.

Отзывы:

- оценка 1–5;
- необязательный комментарий;
- положительные отзывы могут отображаться публично;
- все отзывы доступны администратору.

### 5.9 Админ-панель

Администратор может:

- управлять услугами;
- управлять барберами;
- управлять расписанием;
- управлять исключениями;
- смотреть записи;
- создавать записи вручную;
- менять статусы;
- смотреть отзывы;
- менять базовые настройки.

### 5.10 Аналитика

Минимальный набор:

- выручка;
- количество записей;
- популярные услуги;
- загрузка барберов;
- отмены;
- неявки;
- возвращаемость;
- тепловая карта загрузки.

## 7. Нефункциональные требования

### Дизайн

- современный;
- чистый;
- адаптивный;
- mobile-first;
- светлая и тёмная темы;
- удобные touch-зоны.

### Производительность

Сайт должен оставаться быстрым на мобильных устройствах.

### Время

- в базе все абсолютные даты хранятся в UTC;
- пользователю показываются в `Asia/Tashkent`.

### Язык

MVP — русский.

Архитектура должна позволять позже добавить узбекский язык.

### Безопасность

Обязательно:

- серверная валидация;
- проверка Telegram `initData`;
- секреты только в server environment variables;
- rate limit;
- закрытый прямой доступ к таблицам;
- безопасная админ-сессия;
- защита от двойной записи на уровне базы данных.

## 8. Что не входит в MVP

Пока не реализуем:

- онлайн-оплату;
- программу лояльности;
- SMS;
- расчёт зарплаты;
- полноценную CRM;
- массовые рассылки;
- роли сотрудников;
- несколько филиалов;
- мультиарендность.

---

## 9. Учебный принцип проекта

Проект создаётся последовательно.

Каждый следующий этап решает новую проблему предыдущего:

1. сначала видим сайт;
2. затем делаем форму записи;
3. понимаем, зачем нужна база;
4. понимаем, зачем нужен backend;
5. превращаем макет записи в реальную бизнес-логику;
6. добавляем второй клиент — Telegram Mini App;
7. добавляем Telegram-бота;
8. решаем задачу фоновых уведомлений;
9. даём владельцу управление через админку;
10. добавляем аналитику;
11. публикуем готовый продукт.

После каждого этапа проект должен запускаться и иметь видимый проверяемый результат.

---

## 10. Определение готового MVP

MVP готов, когда:

- сайт доступен через интернет;
- клиент записывается через сайт;
- клиент записывается через Telegram Mini App;
- backend не позволяет создать пересекающуюся запись;
- клиент получает подтверждение;
- клиент получает Telegram-напоминания;
- клиент может отменить или перенести запись;
- администратор управляет услугами, барберами и расписанием;
- администратор видит записи;
- отзывы сохраняются;
- аналитика показывает реальные данные;
- frontend и API задеплоены;
- данные хранятся в Supabase.
